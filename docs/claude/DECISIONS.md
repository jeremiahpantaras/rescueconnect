| D21 | **Staff get near-real-time report updates and in-app notifications, by fast polling (about 8 s) in the Django admin.** No WebSockets, no new infrastructure | Owner request and choices, 2026-10-25 | Responders and LGU staff see a citizen's report within seconds without refreshing | Amends D5: real-time *report updates* are in scope; **live location tracking, live responder tracking, and WebSockets remain out of scope**. | D22 | **Citizens track a report with a random tracking code and a public status page.** The code is 12 characters (Crockford base32, shown XXXX-XXXX-XXXX, 60 bits from `secrets`), shown after submitting, remembered on the device, and usable from any device. New reports start `pending` in the staff queue (no assignment concept yet) | Owner request, 2026-10-25 | Gives no-login citizens a way to see progress without exposing sequential ids | The code is the only credential: the public endpoint returns only type, status, and timestamps (no location, message, photos, device id, or report id). `GET /api/reports/status/<code>/`; pages `/status` and `/status/<code>`; the status page polls every 3 s (no requests while the tab is hidden), see D24; when resolved it hands over to the "Report Resolved" notice, see D25. This is not push notification (D15/P13 still open) |
| D23 | **Each throttle has its own scope** (`report_submit` 10/hour, `staff_login` 10/min, `report_status` 300/min) | Bug found while adding D22, 2026-10-25 | DRF subclasses sharing the default `anon` scope shared one counter per IP: staff-login attempts and status polling would have consumed a citizen's report quota | Regression tests prove the three no longer interfere |
| D24 | **Citizen status page updates in near-real-time by fast polling (3 s), with no manual refresh button** | Owner request, 2026-10-25 | A staff change appears on the citizen's open page within seconds; feels live without new infrastructure | Still polling, not WebSocket push: worst case about 3 s, plus one small request per open page every 3 s (20/min) while the tab is visible. True instant push (Django Channels + Redis + an async server, or SSE on a threaded server) is possible later but adds hosting cost and new failure points. The staff pages keep their 8 s default (`RESCUECONNECT_LIVE_POLL_SECONDS`, minimum 3) |
| D25 | **When a report is resolved the citizen's page becomes a formal "Report Resolved" notice** (`/status/<code>/resolved`): completion statement, thanks, a resolution summary (code, type, submitted, resolved, time to resolution), all four steps completed, "what happens next", Return to map, Print this notice. The status page redirects there live; the notice redirects back if staff reopen the report | Owner request, 2026-10-25 | A clear, professional close-out for the citizen | The wording says only what "resolved" means here (response personnel marked it resolved) and claims no outcome. It uses RescueConnect's own neutral emblem and no official seal or agency name (consistent with D20). A new `resolved_at` field (migration 0008) records the real resolution time: set by `EmergencyReport.save()` for every code path, kept when a resolved report is edited, cleared on reopen; existing resolved reports are backfilled with their last-updated time. It also gives future response-time analytics a source |
| D26 | **The whole system uses the 12-hour clock with AM/PM, never 24-hour** | Owner rule, 2026-10-25 | Consistent, familiar times for citizens and staff | Enforced in code, not by habit. Backend: `tabangnegrosproj/formats/en/formats.py` (via `FORMAT_MODULE_PATH`) sets display and input formats; templates/Python that format times themselves must use `g:i A`, never `H:i`/`G:i`. Frontend: all dates/times go through `src/lib/datetime.ts` (forces `hour12`, overriding the device locale); ESLint (`no-restricted-syntax`) forbids `toLocale*String` and `Intl.DateTimeFormat` elsewhere. Machine data stays ISO 8601 in API JSON. Tests: `reports/tests_timeformat.py` (fails if 24-hour returns), plus a real-browser check in a 24-hour-locale Firefox |
| D27 | **Citizens can make a report with no signal: it is saved on the phone and sent automatically when a connection returns (store-and-forward).** Owner approved "Option 1", 2026-10-25, replacing the earlier exclusion of offline sync for this one case | Owner request | A flood often takes the network down first; a report must not be lost | See ARCHITECTURE.md "Offline reporting". Honest by design: the phone says "saved, NOT yet sent", and staff are never alerted until it arrives. Staff pages stay online-only; no offline maps or SMS fallback (later options). Reports are written to the phone BEFORE the first send, so they cannot be lost; a unique `client_ref` makes repeat sends harmless (no duplicates); the server records when the citizen made it (`reported_at`) so staff can see a report was late |
| D28 | **Django no longer serves the retired Vite app.** `/` redirects to `/admin/`, unknown addresses return 404, and `/sw.js` is a self-removing worker | Bug reported by the owner, 2026-11-02 | The catch-all answered `/admin` (no slash) with the old app, and two older builds (`46bd5fe`, `99976dc`) installed a site-wide worker that answers every page, including `/admin/`, with the saved "Tabang Negros" page | Affected browsers repair themselves on their next visit. Deploying this branch removes the old citizen app from the backend's `/`, so the Next.js frontend must be deployed for citizens. The Capacitor APK only uses the API and is unaffected. Deleting the leftover build files is still P8 |
| D13 | Photos are optional, 0–2 per report | Implemented 2026-10-25; matches the owner's "up to two images" flow | Citizens can report without a camera | `report_type`/severity still not modelled |
